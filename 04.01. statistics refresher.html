Central tendency: what is a typical run?

4.1.1 Why “typical” needs a definition

The owner of Boréal Studio asks a simple question: how long does e-mail triage take? No single run answers it, because no two runs take exactly the same time. A measure of central tendency is one number that represents the centre of a set of values. Statistics offers three standard ones — the mean, the median and the mode. They agree only when the values are spread evenly around one centre; when they disagree, the disagreement is itself information, because it shows that some values lie far from the others.

Notation used in this lesson: n is the number of observations (here, the number of runs) and x₁, x₂, …, xₙ are the observed values (minutes per run). The symbol Σ (capital sigma) means “add up”: Σx is the sum of all the values.

4.1.2 The mean

The arithmetic mean (usually just the mean) is the sum of the values divided by their number:

x̄ = (x₁ + x₂ + … + xₙ) / n = Σx / n

The symbol x̄ (“x-bar”) denotes the mean of a sample. The mean uses every value, which is both its strength and its weakness: a single very large value changes it. In Python, sum(values) / len(values) computes it; statistics.mean(values) does the same with extra care for floating-point precision.

Worked example — one week of e-mail triage for S2 (illustrative values): Monday 105, Tuesday 36, Wednesday 33, Thursday 38, Friday 34 minutes. Σx = 246, n = 5, so x̄ = 246 / 5 = 49.2 minutes. Four of the five runs took between 33 and 38 minutes, yet the mean is longer than every run except Monday's. Monday is long because the inbox holds the mail of a whole weekend: the backlog almost triples the time of the run.

4.1.3 The median

The median is the middle value of the data once they are sorted. With an odd n, it is the value in position (n + 1) / 2; with an even n, it is the average of the two values in positions n / 2 and n / 2 + 1. Sorting always comes first: the “middle” of an unsorted list is just an arbitrary value.

For the week: sorted, the values are 33, 34, 36, 38, 105; n = 5, the middle position is 3, so the median is 36 minutes. Remove Monday and four values remain — 33, 34, 36, 38 — so the median is the average of positions 2 and 3: (34 + 36) / 2 = 35 minutes. The median moved by one minute; the mean moved from 49.2 to 35.25 minutes.

The median depends on the order of the values, not on how far the extreme ones are from the centre. Monday could take 500 minutes and the median of the week would still be 36. A measure with this property is called resistant (or robust) to outliers. An outlier is an observation that lies unusually far from the other values of the data set; Lesson 4.3 gives two rules that define “unusually far”.

In code: sort a copy with sorted(values) (the caller's list keeps its order), find the middle index with n // 2, and branch on n % 2. Python counts positions from 0, so the third value of a sorted list is ordered[2].

4.1.4 The mode, and what to do with ties

The mode is the value that occurs most often. It is the natural centre for discrete counts — values that can only be whole numbers, such as the number of interruptions during a run. During S2's week the interruptions were 5, 1, 0, 2, 1: the value 1 occurs twice and every other value once, so the mode is 1 interruption.

For measured times, the mode is often of little use. In the teaching copy, three values tie for the most frequent among the 55 manual e-mail triage runs: 29, 32 and 37 minutes, five runs each. A data set with two modes is bimodal; with more than two, multimodal. Decide in advance what your code returns when values tie, and write the decision in the docstring: statistics.mode returns the first mode it meets in the data (Python 3.8 and later), while statistics.multimode returns all of them in a list. JARVIS's StatsEngine.mode will return the list of tied values, like multimode.

▶ Slide 12 · The range

4.1.5 The range

The range is the largest value minus the smallest one: for the week, 105 − 33 = 72 minutes. It is quick to compute and easy to misread, because it depends on two values only — the two most extreme runs. One unusual Monday decides it alone. The range describes spread, not centre; Lesson 4.2 replaces it with measures that use every value.

▶ Slide 13 · Which number describes a typical run?

4.1.6 Which number describes a typical run?

The rule used in this course:

  • Report the median when the data contain a few extreme values or a long tail on one side; it describes the run that a staff member experiences on a normal day.
  • Report the mean when the values are roughly symmetric, and whenever the number will be multiplied: a monthly total is mean × number of runs, because Σx = n · x̄ exactly.
  • Report both, with the reason, when they differ by more than a few percent.

In the full teaching log the six routines are close to symmetric, so the two measures agree within one minute. The week with the backlog is where they separate.

Key terms of Lesson 4.1

Measure of central tendency
One number that represents the centre of a set of values: mean, median or mode.
Mean (x̄)
Sum of the values divided by their number, Σx / n. Uses every value; changed by extreme values.
Median
Middle value of the sorted data; average of the two middle values when n is even.
Resistant (robust) measure
A measure that one extreme value cannot move far — the median, unlike the mean.
Mode
Most frequent value; useful for discrete counts; several modes are possible (bimodal, multimodal).
Discrete count
A variable that takes whole-number values only, such as interruptions per run.
Range
Largest value minus smallest value; decided by the two most extreme observations.
Outlier
An observation unusually far from the other values; defined by a stated rule (Lesson 4.3).

    ▶ Slide 17 · 4.2 Same centre, different reliability
    4.2.1 Same centre, different reliability
    Two routines can share a mean and still behave very differently. Take two sets of five runs, both with a mean of 10 minutes: A = 8, 10, 9, 12, 11 and B = 4, 16, 6, 15, 9. A planner can rely on A's 10 minutes, because no run is more than 2 minutes away from it. B's 10 minutes is a poor guide: individual runs range from 4 to 16 minutes.
    

    Dispersion (also called spread or variability) measures how far the values typically lie from their centre. For JARVIS it matters twice: a routine with a large spread is hard to schedule, and the savings estimated in Class 3 for that routine are less certain.
    ▶ Slide 18 · Deviations always add up to zero
    4.2.2 Deviations
    The deviation of a value is its signed distance from the mean: dᵢ = xᵢ − x̄. For A (x̄ = 10): 8 − 10 = −2, 10 − 10 = 0, 9 − 10 = −1, 12 − 10 = +2, 11 − 10 = +1.
    

    The deviations of any data set add up to zero: −2 + 0 − 1 + 2 + 1 = 0. This follows from the definition of the mean, which is exactly the value that balances the positive and the negative deviations. Their average is therefore always 0 and says nothing about spread. Squaring each deviation removes the sign, so that every value contributes a positive amount.
    ▶ Slide 19 · Sample variance and standard deviation
    4.2.3 Sample variance and standard deviation
    The sample variance is the sum of the squared deviations divided by n − 1:
    

    s² = Σ(xᵢ − x̄)² / (n − 1)     s = √s²
    


    For A, the squared deviations are 4, 0, 1, 4, 1. Their total — the sum of squares — is 10, so s² = 10 / 4 = 2.5 min². The unit is squared minutes, which has no practical meaning, so we take the square root: the sample standard deviation is s = √2.5 ≈ 1.58 minutes. Read it as: a run typically lies about 1.6 minutes from the mean.
    

    For B, the deviations are −6, +6, −4, +5, −1, the sum of squares is 36 + 36 + 16 + 25 + 1 = 114, s² = 114 / 4 = 28.5 and s ≈ 5.34 minutes — more than three times the spread of A, with the same mean.
    ▶ Slide 20 · Why n − 1? Sample versus population
    4.2.4 Why n − 1? Sample versus population
    A population is the complete set of values we want to describe; a sample is the part we actually observed. Boréal's 14 days are a sample of all the days the studio has worked and will work.
    

    The deviations of a sample are measured from the sample's own mean, and that mean is, by construction, the point that makes the sum of squared deviations as small as possible. Measured from the true population mean, the same values would give a larger sum. Dividing the sample sum by n therefore underestimates the population variance on average; dividing by n − 1 corrects this. The number n − 1 is called the degrees of freedom: once the mean is fixed, only n − 1 deviations can vary freely, because all n of them must add up to zero.
    

    In Python, statistics.variance and statistics.stdev divide by n − 1 (sample); statistics.pvariance and statistics.pstdev divide by n (population). For A, stdev gives 1.581 and pstdev gives 1.414. JARVIS's StatsEngine uses n − 1, because our data are a sample. The spreadsheet equivalents are STDEV.S (sample) and STDEV.P (population).
    ▶ Slide 21 · The coefficient of variation
    4.2.5 The coefficient of variation
    A standard deviation is expressed in the unit of the data, so it tends to grow with the size of the values: a 6-minute spread is moderate for a 35-minute routine and very large for a 10-minute one. The coefficient of variation (CV) divides the standard deviation by the mean:
    

    CV (Coefficient of Variation) = s / x̄   (usually × 100, in %)
    


    The CV (Coefficient of Variation) has no unit, so it compares variability across routines of different length. For A: CV = 1.58 / 10 = 15.8 %; for B: 5.34 / 10 = 53.4 %. The CV is meaningful only for data measured from a true zero (minutes, dollars, counts) and with a mean that is clearly above zero.

      ▶ Slide 29 · Shape: symmetric, skewed, bimodal
      4.3.3 Shape: symmetric, skewed, bimodal
      A distribution is symmetric when its left and right halves are approximately mirror images; then the mean and the median are close. It is right-skewed (or positively skewed) when the values thin out slowly towards the large values — a long right tail — and then the mean is larger than the median. Durations are often right-skewed: a run cannot be shorter than a certain minimum, but a backlog, a difficult request or several interruptions can make it much longer. A left-skewed distribution has the long tail on the side of the small values.
      

      The manual e-mail triage runs show a weak version of the right skew: most runs lie between 25 and 44 minutes, and four runs continue the tail up to 51 minutes; the mean (35.15) is only slightly above the median (35). A histogram also reveals bimodal shapes. Add the 15 jarvis runs (10 to 19 minutes) to the 55 manual runs and the histogram shows two separate peaks — the visible sign that two different processes were put into one list.
      ▶ Slide 30 · Quartiles and the IQR (Interquartile Range)
      4.3.4 Quartiles and the interquartile range
      The quartiles divide the sorted data into four parts that contain about the same number of values. Q1 (first quartile) (the first quartile) has about 25 % of the values below it, Q2 (second quartile) is the median, and Q3 (third quartile) (the third quartile) has about 75 % below it.
      

      Several conventions exist for computing quartiles. This course uses the inclusive method (linear interpolation): sort the n values, number their positions from 0 to n − 1, compute the position p × (n − 1) for p = 0.25 or 0.75, and interpolate between the two neighbouring values when the position is not a whole number. It is the method of statistics.quantiles(values, n=4, method="inclusive"), of the spreadsheet function QUARTILE.INC and of NumPy's default. Python's default for quantiles() is method="exclusive", which gives slightly different values — so always state the method you used.
      

      For the 55 runs: the Q1 (first quartile) position is 0.25 × 54 = 13.5, between the sorted values at positions 13 and 14 (30 and 31), so Q1 = 30.5 minutes; the Q3 (third quartile) position is 0.75 × 54 = 40.5, between 39 and 40, so Q3 = 39.5 minutes. The interquartile range is IQR (Interquartile Range) = Q3 − Q1 = 9 minutes: the middle half of the runs lies in a 9-minute window. Like the median, the IQR is resistant to extreme values.

      4.3.6 Two outlier rules
      An outlier rule must be chosen before looking at which runs it flags; a rule adjusted after the fact simply produces the answer that someone preferred. Two rules are standard:
      

        

      • The 1.5 × IQR (Interquartile Range) rule (Tukey's fences): a value is an outlier if it lies below Q1 (first quartile) − 1.5 × IQR or above Q3 (third quartile) + 1.5 × IQR. The two limits are called fences. For the e-mail runs: 30.5 − 13.5 = 17 and 39.5 + 13.5 = 53 minutes. No manual run lies outside [17, 53], so the rule flags no outlier.
        • 

      • The mean ± 2 SD (Standard Deviation) rule: a value is flagged if it lies more than two standard deviations from the mean: 35.15 ± 2 × 6.35 gives [22.44, 47.85]. Two runs are flagged: 48 minutes (S3, Monday, September 14 — the first day of the log) and 51 minutes (S5, Friday, September 18, with 3 interruptions).
        • 

      

      The two rules disagree, and both have been applied correctly. The 1.5 × IQR (Interquartile Range) rule is built on quartiles, which the extreme values themselves barely affect. The mean ± 2 SD (Standard Deviation) rule is built on the mean and the SD, which the extreme values raise; it also flags about 5 % of the values of perfectly regular, bell-shaped data. Write your rule and its reason in one sentence, for example: “We flag runs outside Q1 (first quartile) − 1.5·IQR and Q3 (third quartile) + 1.5·IQR (inclusive quartiles), because quartiles are not changed by the runs being judged.”
      ▶ Slide 33 · What to do with a flagged run
      4.3.7 What to do with a flagged run
      A flagged value is a question, not a mistake. Check it against the log first. The 51-minute run had three interruptions; the 48-minute run is a Monday morning after a weekend. Neither is a typing error. Three decisions are possible:
      

        

      1. Keep it — it is a real run. This is the default.
        2. 

      2. Correct it — only when it is a proven data-entry error (for example 510 typed instead of 51), and with the correction recorded in the bug log.
        3. 

      3. Report it separately — give the result with and without the flagged runs when they change a conclusion.
        4. 

      

      Never delete a value silently. Removing the 51-minute run would make e-mail triage look cheaper than it is, and the monthly cost of about 1 640 $ computed in Class 3 would be understated.

        4.4.1 Scatter plots
        A scatter plot shows two numeric variables measured on the same runs: one point per run, the first variable on the horizontal axis (x) and the second on the vertical axis (y). By convention x is the explanatory variable — the one we think may influence the other (interruptions) — and y is the response variable — the one we want to explain (minutes).
        

        Read a scatter plot for three properties: the direction (points rise from left to right — a positive relationship — or fall — a negative one), the form (along a straight line, along a curve, or without pattern) and the strength (how closely the points follow that form). When x is a discrete count, as interruptions are (0 to 5), many points share the same x-value; moving each point by a small random horizontal amount, called jitter, keeps them visible without changing their y-values.
        ▶ Slide 38 · Pearson's correlation coefficient r
        4.4.2 Pearson's correlation coefficient r
        Pearson's correlation coefficient, written r, measures the direction and the strength of the linear relationship between x and y:
        

        r = Σ(xᵢ − x̄)(yᵢ − ȳ) / √[ Σ(xᵢ − x̄)² · Σ(yᵢ − ȳ)² ]
        


        The numerator adds up the products of the two deviations of each run. A run with more interruptions than average (positive x-deviation) and more minutes than average (positive y-deviation) adds a positive product; so does a run below average on both. A run above average on one variable and below on the other adds a negative product. The denominator rescales the total so that r always lies between −1 and +1, whatever the units.
        

        r = +1 means that all points lie on a rising straight line; r = −1, on a falling straight line; r close to 0 means no linear relationship (a curved one may still exist). r has no unit, and swapping x and y does not change it. In Python: statistics.correlation(xs, ys), available since Python 3.10.

        4.4.6 What 14 days and five people can and cannot show
          

        • Correlation is not causation. r measures association. A third variable, a confounding variable, can influence both x and y: on Mondays there is more mail and more interruptions (manual Monday runs average 37.6 minutes, other days 34.5). A relationship between interruptions and minutes may be partly a relationship of both with the day of the week.
          • 

        • Sample size. At most 70 runs per routine; the jarvis result rests on 15 runs by three people over five days. Results from such a sample suggest; they do not prove. A longer log, with more people, narrows the uncertainty.
          • 

        • Scope. Five people of one studio during three September weeks are not “consultancies in general”, and September may not represent December. Write the scope next to every conclusion: Boréal Studio, 14 working days, September 14 – October 1, 2026.
          • 

        • Measurement. Minutes were logged by the staff themselves; people round to the nearest 5 minutes and forget short runs. The jarvis runs are timed by the assistant — a different measurement process from manual logging.
          • 

        • Novelty. A new template or tool is often used with extra care in its first days, and its effect can shrink later.

        What this code doesCompute Pearson's r from its definition for three pairs of variables (manual runs), build the before/after table of the daily-report template, compare the e-mail pilot group with the comparison group, and check our r against statistics.correlation.

        #!/usr/bin/env python3# -*- coding: utf-8 -*-# relationship.py — CS 251, Class 4, Example 4.4# Task: Pearson's r for three pairs, the before/after table of the daily-report template,#       and the e-mail pilot against its comparison group.# Boréal Studio is a fictional teaching case; the data are synthetic (Cyber.SoHo Notice, section 4.2).# Run from the package folder (the one that contains code/ and data/):  python code/relationship.py# Standard library only: no installation is needed beyond Python 3.10 or later. # Import the csv module to read the teaching dataset.import csv# Import math for the square root and isclose.import math# Import statistics for means, SDs and the oracle correlation().import statistics# Import Path to locate the data file relative to this script.from pathlib import Path # Define Pearson's correlation coefficient from its formula.def pearson_r(xs, ys):    # Both lists must describe the same runs (equal length) and contain at least two runs.    if len(xs) != len(ys) or len(xs) < 2:        # Stop with a clear message when the input cannot give a correlation.        raise ValueError("pearson_r() needs two lists of equal length, at least 2")    # Mean of the explanatory variable x.    mean_x = sum(xs) / len(xs)    # Mean of the response variable y.    mean_y = sum(ys) / len(ys)    # Sum of the products of deviations: positive when a run is above (or below) both means.    sxy = sum((x - mean_x) * (y - mean_y) for x, y in zip(xs, ys))    # Sum of squares of x.    sxx = sum((x - mean_x) ** 2 for x in xs)    # Sum of squares of y.    syy = sum((y - mean_y) ** 2 for y in ys)    # Rescale by the square root of the product, so that r is unit-free and lies between −1 and +1.    return sxy / math.sqrt(sxx * syy) # Build the path of the teaching dataset.data_file = Path(__file__).resolve().parent.parent / "data" / "boreal_routines_2026.csv"# Open the file; the with-block closes it automatically.with data_file.open(encoding="utf-8") as handle:    # Read all rows as dictionaries.    rows = list(csv.DictReader(handle)) # Helper: one numeric column for one routine and one tool, in file order.def column(routine, field, tool="manual"):    # The same filter for x and y keeps the two lists aligned run by run.    return [int(r[field]) for r in rows if r["routine"] == routine and r["tool"] == tool] # Visit the three pairs of the lesson: (x field, minutes) for a routine.for routine, field in (("standup_notes", "interruptions"), ("email_triage", "interruptions"), ("email_triage", "start_hour")):    # Compute r between the chosen field and the minutes of the same runs.    r = pearson_r(column(routine, field), column(routine, "minutes"))    # Print r with its sign and three decimals.    print(f"r({field}, minutes) {routine:<14} = {r:+.3f}")# Daily-report runs before the template: days 1–7, tool = manual.before = column("daily_report", "minutes", "manual")# Daily-report runs from day 8, written with the template.after = column("daily_report", "minutes", "template")# Visit the two groups of the before/after table.for label, values in (("before (manual)", before), ("after (template)", after)):    # Print n, mean and SD: a mean is never reported without them.    print(f"{label:<17} n = {len(values)}  mean = {statistics.mean(values):.2f}  SD = {statistics.stdev(values):.2f}")# Difference of the means, after minus before.change = statistics.mean(after) - statistics.mean(before)# Print the difference in minutes and as a percentage of the 'before' mean.print(f"difference = {change:+.2f} min per run ({change / statistics.mean(before) * 100:+.1f} %)")# Visit the pilot group and the comparison group of the e-mail assistant.for label, staff in (("pilot S1-S3", ("S1", "S2", "S3")), ("comparison S4-S5", ("S4", "S5"))):    # Days 1–9 (before September 25): ISO dates compare correctly as text.    early = [int(r["minutes"]) for r in rows if r["routine"] == "email_triage" and r["staff_id"] in staff and r["date"] < "2026-09-25"]    # Days 10–14: jarvis runs for the pilot group, manual runs for the comparison group.    late = [int(r["minutes"]) for r in rows if r["routine"] == "email_triage" and r["staff_id"] in staff and r["date"] >= "2026-09-25"]    # Print both periods and the change of each group.    print(f"{label:<17} days 1-9: {statistics.mean(early):.2f}  days 10-14: {statistics.mean(late):.2f}  change: {statistics.mean(late) - statistics.mean(early):+.2f}")# Prepare one pair for the oracle check.xs, ys = column("email_triage", "interruptions"), column("email_triage", "minutes")# Oracle check: our r must equal statistics.correlation (Python 3.10 and later).assert math.isclose(pearson_r(xs, ys), statistics.correlation(xs, ys))# Confirm that the check passed.print("Oracle check passed: pearson_r agrees with statistics.correlation.")
